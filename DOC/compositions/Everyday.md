# Everyday composition family

Everyday demonstrates that the same MetaModule model can be used outside traditional enterprise application boundaries.

Current example profiles include:

- Shopping
- Pantry
- Meals
- Tasks
- Habits
- Budget
- Subscriptions
- Warranty
- Inventory
- Packing
- Travel
- Events
- Family
- Medication
- Workout
- Reading
- Watchlist
- Wishlist
- Gifts
- Maintenance
- Logbook

These are Composition/profile examples over reusable primitives.

They do not automatically create new Universal families.

For example, a Tasks view does not require a separate Task primitive if the needed semantics can be expressed through recursive Project structure and contextual projection.

Everyday is therefore another proof that application naming does not determine canonical data ownership.
