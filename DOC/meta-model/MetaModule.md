# MetaModule model

A MetaModule is the reusable structural unit through which existing capabilities are assembled into useful system behavior.

For Composition-oriented MetaModules, the practical meaning is:

> Take these existing capabilities, connect them this way, and present/use them this way.

The defining property is reuse of canonical semantics rather than ownership of duplicate truth.

## MetaModule responsibilities

A MetaModule may describe:

- membership,
- references to Universals,
- Composition-specific relations,
- Composition-specific rules,
- Projections,
- presentation structure,
- SiteTree structure,
- defaults,
- constraints,
- allowed combinations,
- capability arrangement.

It does not gain authority to duplicate semantic meaning already owned by a Universal.

## MetaModule and application

Traditional application boundaries such as ERP, CRM, WMS, HRM, Strategy or Everyday are treated as Composition boundaries rather than new canonical data silos.

Therefore:

```text
application identity != canonical truth ownership
```

A MetaModule can be replaced while the underlying canonical business truth remains intact.
